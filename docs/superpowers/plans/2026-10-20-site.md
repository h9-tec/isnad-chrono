# isnad-chrono explorer (GitHub Pages) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static site at `https://h9-tec.github.io/isnad-chrono/` that draws each report's merged transmission tree with its common link, edit badges and narrator dates, plus narrator pages, an atlas, leaderboards and a method page.

**Architecture:** A new CLI stage `export-site` turns the v2 parquet outputs into sharded JSON under `site_data/` (gitignored). The JSON is committed to an orphan branch `site-data`; the Pages workflow checks out `site/` from `main` and `site-data` into `_site/data/` and deploys. The site is hand-written HTML/JS/CSS with vendored D3, no build step; locally it runs with `python -m http.server` from the repo root.

**Tech Stack:** Python 3.12, pandas/pyarrow (existing), `jsonschema` (test dep), D3 v7 (vendored), GitHub Actions `actions/upload-pages-artifact` + `actions/deploy-pages`.

**Spec:** `docs/superpowers/specs/2026-10-20-site-design.md`

## Global Constraints

- Names shown are `abbrev` (fallback `name`) and `kunya` from `data/rawi.parquet`; **no hadith text, matn, statement, `*_text`, `narrative_years`, `name_forms`, `lineage` may appear in any site JSON** (spec §3 denylist; test in Task 1 runs over every file written).
- Links: narrator `https://hdith.com/encyclopedia/rawi/p-<id>`, hadith `https://hdith.com/encyclopedia/book/<book_slug>/h/<hadith_id>`.
- Group shard = last two decimal digits of N in `tk-N`, zero-padded (`tk-7` → `07`); narrator shard = last two digits of the id, zero-padded. Paths `groups/<shard>/<group_id>.json`, `narrator/<shard>/<id>.json`.
- Years are ints (Hijri), rates rounded to 3 decimals, ids ints, JSON written with `ensure_ascii=False`, `separators=(",", ":")`.
- Page weight: `narrators.json` ≤ 3 MB, any group JSON ≤ 200 KB (test in Task 2 on the real export).
- Chains in site JSON are **cleaned** (`tree.clean_chains`), Companion first, compiler last. Chain orientation everywhere: position 0 = earliest narrator.
- Arabic-first RTL UI; mobile one-column; D3 vendored at `site/vendor/d3.v7.min.js` (7.9.0).
- Stage 3 fetch workers run in this worktree: no `fetch`, no writes under `data/raw` or to `data/queue.sqlite`, no process kills. The existing 309 tests stay green. No Co-Authored-By trailers.

## Review Focus

1. A group whose chains all collapse to one narrator after cleaning (single-node chains dropped) must still render: nodes list may be empty and the side panel says "no parsable chains" (Task 2 test `test_group_json_without_chains`).
2. A narrator present in chains but absent from `rawi.parquet` (placeholder ids 1 and 2 are already excluded by chains; others may be missing after Stage 3) must get name `p-<id>` not a crash (Task 1 test `test_narrators_missing_name_falls_back`).
3. Search input with Arabic digits or extra spaces (`مسلم  ٢٨٦٤`) must resolve like `muslim 2864` (Task 3: `normalizeQuery` test via the Python mirror `search_key` in Task 1 `test_search_key_normalises_digits`).
4. Groups with two roots (cross-root carriers) must draw two components side by side, not one tree with a fake root (Task 3 visual check list; Task 2 test `test_group_json_two_roots`).
5. A narrator page for an id with no detail shard (narrator with chains but no teachers/students) must render the summary from `narrators.json` and say "no links" (Task 4; Task 2 test `test_narrator_detail_written_for_every_chain_narrator`).
