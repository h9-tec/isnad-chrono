# isnad-chrono explorer: static site on GitHub Pages

Date: 2026-10-20. Status: approved in conversation (user: "show names, same repo"). Repo `h9-tec/isnad-chrono` (created 2026-10-20, `main` pushed). Builds on the v2 dataset (`2026-10-20-corpus-icma-design.md`, HF `HeshamHaroon/isnad-chrono` v0.1.1).

## 1. Goal
A static, server-less site at `https://h9-tec.github.io/isnad-chrono/` that lets anyone open a hadith report and see its merged transmission tree, the common link with its death interval, who introduced which wording changes, and every narrator's inferred dates. It is the public face of the dataset and the demo for the paper.

Decisions:
- **Narrator names are shown** (short name `abbrev` from the cached narrator pages, first kunya only: the hdith.com field is cut before its editorial notes, see §3). Names of classical transmitters are public facts; each narrator links to its hdith.com page `https://hdith.com/encyclopedia/rawi/p-<id>` as attribution.
- **Hadith text is never shown or shipped.** Each occurrence links to its hdith.com page `https://hdith.com/encyclopedia/book/<book_slug>/h/<hadith_id>`.
- **Same repo**: code in `site/` (hand-written HTML/JS/CSS, no build step), data exported by a new CLI stage `export-site` into `site_data/` (gitignored) and published as the orphan branch `site-data` (one commit, force-pushed on refresh; no tarball, no release asset) that the Pages workflow checks out into `_site/data/` at deploy. `main` stays small and v0.2 refreshes the site by re-pushing `site-data`. `export-site --checks release_hf/checks.json` copies the release checks into `meta.json`; an explicit `--checks` path that does not exist is an error (exit 2).
- Narrator names, kunyas and transmission terms come from hdith.com and are not covered by the CC-BY license of the derived numbers; README and every page footer say so.
- Arabic-first UI (RTL), English labels secondary. Mobile works (one column, tree scrolls horizontally).

## 2. Pages
1. **Home / Report explorer** (`index.html`): search box accepting a book + hadith number (e.g. `bukhari 10`, `مسلم 2864`), a hadith id, a group id (`tk-N`), or a narrator name (prefix match over a client-side index). Result: the group's merged tree drawn with D3 (top-down: Companion root(s) at the top, compilers as leaves at the bottom; one component per root). Node label = short name + death interval; colour by `method` (known / inferred / prior_only); the k2 common link gets a ring and a badge "CL k2 · d. lo–hi", k3 CL a second ring; partial common links a dashed ring. Edit badges: a node that introduced n wording changes (status attributed or ambiguous) shows "n" in a small pill; hover lists the segment numbers and edit types. Edges carry the transmission term (حدثنا / عن …) on hover. Side panel: group facts (n occurrences per book with links to hdith.com, complete flag, n chains, shawahid companions), report date line "earliest datable transmitter: NAME, died between lo and hi AH", and the edit summary (attributed / ambiguous / partial / no_chain counts).
2. **Narrator page** (`narrator.html?id=N`): name, kunya, generation, recorded birth/death with kind, inferred intervals on a horizontal timeline (recorded as a point, inferred as a bar, prior-only as a faint bar), `support`, number of chains through them, teachers and students (top 20 by shared chains, with names), reports where they are the k2 common link (table, links to the explorer), links dropped by the dating step that touch them.
3. **Atlas** (`atlas.html`): (a) histogram of k2 common-link death years (bin 10 y) with a compiler filter; (b) the drift curve: edit rate and non-leaf edit rate per generation depth with n; (c) coverage table from `checks.json` (chains, groups, CL rates, dating hold-out, alignment).
4. **Leaderboards** (`boards.html`): most frequent common links (by number of groups, with names), earliest datable reports (lowest `cl_k2_date_hi`), narrators with the widest known-vs-inferred conflict (recorded death year outside the inferred interval), top edit introducers (attributed edits, with their transmission count so rate is visible).
5. **Method** (`method.html`): the dataset card's method and checks sections rendered as HTML with the live numbers, links to HF and the paper.

## 3. Data files (`export-site`, output `site_data/`)
All JSON, UTF-8, ids as ints, years as ints (interval bounds rounded outward), rates rounded to 4 decimals.
- `meta.json`: version, build date, cached page count, checks (flattened as in the release), book list `{slug, title, n_hadith_cached}`.
- `narrators.json`: columnar `{cols: [id, name, kunya, gen, dy, dk, by, bk, dlo, dhi, blo, bhi, method, support, n_chains, placeholder], rows: [[…]…]}` for every narrator with at least one chain (about 16k; ~2 MB). Names from `data/rawi.parquet` (`abbrev`, else `name`); narrators missing from `rawi.parquet` get `p-<id>`; ids 1 and 2 are placeholders (`placeholder: true`, name «راوٍ غير مسمّى») and are kept off every board. `kunya` is the first kunya only: the text before the first of `،` `,` `.` `:` `؛` ` ويقال` ` وقيل` ` وفي ` ` قال `, kept only if it starts with أبو/أبا/أبي/أم/ابن/أ and has at most 40 chars, else null (hdith.com appends editorial notes of up to 152 chars). `dy/by` recorded years, `dk/bk` kinds.
- Search, sharded and lazy: `search.json` = `{books: {slug: title}, aliases: {alias: slug}}`; `search/n/<slug>.json` = `{numbering: {"<numbering>": [group_id…]}}`; `search/h/<NN>.json` (NN = hadith_id mod 100, two digits) = `{"<hadith_id>": [group_id…]}`. Values are lists of string group ids (`tk-N` / `tg-N`), sorted; a key in several groups shows a chooser. Narrators are searched from `narrators.json` client-side.
- `groups/<shard>/<group_id>.json` where shard = the last two decimal digits of N in `tk-N`: `{id, complete, all_chained, books: {slug: [hadith_id…]}, chains: [[rawi_id…]…] (cleaned, Companion first), roots: [rawi_id], nodes: [{id, root, depth, k, n_desc, cl2, cl3, pcl2, pcl3}], cl: {k2: {id, lo, hi, method, all_chains}, k3: {…}}, edits: {attributed: n, ambiguous: n, partial: n, cross_root: n, no_chain: n, no_common_node: n, by_node: {rawi_id: [{seg, type, status}]}, by_node_external: [{id, seg, type, status}]}, terms: {"<teacher>-<student>": term}, shawahid: [rawi_id…]}`. Terms come from `chains.parquet` (term on the teacher row).
- `narrator/<shard>/<id>.json` (shard = last two digits of id): `{teachers: [[id, n]…], students: [[id, n]…], cl_groups: [[group_id, lo, hi]…], dropped: [[other_id, reason]…]}`.
- `atlas.json`: `{cl_hist: {compiler_slug: [[bin_start, n]…], all: […]}, cl_hist_excluded: {prior_only: n, unbounded: n}, drift: edit_rates rows, boards: {top_cls: [[id, n_groups]…], earliest: [[group_id, cl_id, lo, hi]…], conflicts: [[id, n_dropped, dy]…], top_editors: [[id, n_edits, n_chains]…]}}`. `cl_hist` counts only k2 CLs with a bounded interval (hi − lo ≤ `dating.BOUNDED_WIDTH`), the rest are counted in `cl_hist_excluded`; `conflicts` = top 50 narrators by dropped dating links touching them (`dy` recorded death year or null; the recorded-vs-inferred distance is ~0 by construction, so the board shows the most dropped links instead); `top_editors` third value is the narrator's `n_chains` (as in `narrators.json`), not a transmission count; rates use 4 decimals; year bounds are rounded outward (lo floor, hi ceil).
Denylist for the site data, enforced by a test: no key may be `text`, `matn`, `statement`, `*_text`, `narrative_years`, `name_forms`, `lineage`; only `name` and `kunya` are allowed name-like keys.

## 4. Delivery
- `site/`: `index.html`, `narrator.html`, `atlas.html`, `boards.html`, `method.html` (no router; each page loads `data.js` + `common.js` and its own script), `data.js` (fetch + cache + shard paths), `common.js` (shared helpers: `esc`, `narratorName`, `narratorLink`, `arNorm`, `asciiDigits`, sortable tables, check formatting, status line), `explorer.js` (search + group panel, `index.html`), `tree.js` (D3 layout by longest path from the root + drawing), `narrator.js`, `atlas.js`, `boards.js`, `styles.css`, `vendor/d3.v7.min.js` (vendored, pinned v7.9.0, with its license). Data base path: `../site_data/` when the host is `localhost` / `127.0.0.1` (repo root served by `python -m http.server`), else `./data/` (Pages or a custom domain).
- `.github/workflows/pages.yml`: on push to `main` and `workflow_dispatch`; checks out `main` and the `site-data` branch into `_site/data` (both `persist-credentials: false`), copies `site/` into `_site/`, fails unless `_site/data/meta.json` exists, deploys with `actions/deploy-pages`. `.github/workflows/validate.yml`: `uv run pytest -q` on push/PR.
- `export-site` CLI: `--data-dir data --out site_data [--checks release_hf/checks.json]` (default: that file when present). Re-export wipes `groups/`, `narrator/`, `search/` under `--out` first (refuses an `--out` that is or contains the data dir, the repo root or the cwd). Publishing = force-push `site_data/` as the orphan `site-data` branch (README), then re-run `pages`.
- Repo README gets an "Explore" section describing the five pages, and every page a footer: data from hdith.com (link), dataset on HF (link), code (link), CC-BY-4.0 for derived numbers, no hadith text redistributed, names/kunyas/terms from hdith.com outside CC-BY.

## 5. Checks (as implemented)
- `tests/test_export_site.py`: denylist (`write_json` rejects denylisted keys anywhere); group, narrator-detail and atlas objects validate against JSON schemas on fixture data; search shards keep every group of a duplicated key; `bukhari 10` resolves at the `search_tables` level (alias → `b-1`, Arabic-Indic digits); kunya trimming (editorial note → null, «أبو عمارة ، ويقال : أبو عمار» → «أبو عمارة»); placeholders off the boards; years rounded outward; bounded-only histogram; missing `--checks` fails; re-export drops stale files.
- Real-export tests (skip when `site_data/` is absent): `narrators.json` ≤ 3 MB, every group JSON ≤ 200 KB, every search shard ≤ 600 KB, `atlas.json` matches its schema, and no JSON string in `site_data/` is longer than 80 chars except `meta.books[].title`.
- `tests/test_site_layout.py` (skips when `node` is absent): runs `site/tree.js` with the vendored d3 under node on a fixture group with a cycle; asserts every chain is embedded and every edge goes down a layer or is flagged `back`.
- `tests/test_site_static.py`: no external scripts or stylesheets, pinned d3 with license, every page has the nav, `data.js`/`common.js` and the footer (incl. the hdith.com names clause), method/atlas check keys exist in `release_hf/checks.json`, workflow hardening. Visual checks by hand in headless Chrome are recorded in the run record.

## 6. Out of scope (v2 of the site)
Hadith text display, diff view of variants (needs text), dynamic search over 600k hadith numbers of all 245 books (v0.2 data), i18n beyond Arabic/English labels.
